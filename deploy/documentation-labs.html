Labs

What Labs is

OF1 Labs is an automated demo factory. Give it the address of any website and it produces a live, AI-generated demonstration of what OF1 can do for that brand — no manual build, no code to write. Under the hood it drives Claude Code through a repeatable pipeline packaged as a reusable AI skill, and publishes the result on AEM Edge Delivery Services.

It's the fastest way to go from "here's a website" to "here's that website, personalized." Sales and solution teams use it to spin up tailored demos; the of1 team uses it to test the generation pipeline against real sites.

OF1 Labs vs. OF1 Product
OF1 Labs is the factory that builds a demo. OF1 Product is what personalizes each page for each visitor once the site is live. Labs sets a site up; the product runs it.

Step by step, here's what each stage actually does:

1
Sign in & submit
You sign in with your Adobe account, pick an experiment type, and paste the target website's URL. That's the entire manual step — everything after is automatic.
2
Provision a workspace
Labs creates a fresh project from the AEM boilerplate, registers it with AEM Edge Delivery Services so it has a live preview address, and grants you access to author and publish it.
3
Run the pipeline
Claude Code runs headless in an isolated sandbox, following a versioned skill. It studies the target site, rebuilds it as an of1 site, and wires up everything needed for personalization. See the OF1 pipeline.
4
Report progress & deliver
Each step reports as it starts and finishes, so you can watch the run move along. When it's done the status turns ready and you get an email with a link to the live AEM preview.

Experiment types

One button, three kinds of transformation. You choose the type when you start a run.

TypeWhat it producesGood for
OF1 demoA personalized of1 version of the target site — the full generative-website experienceShowing what of1 does for a specific brand
Stardust redesignA fresh, modern redesign of the site in the Stardust styleDemonstrating an AI-driven visual refresh
Liftoff migrationAn existing page migrated onto AEM Edge DeliveryShowing a low-effort path onto modern AEM

Every experiment is built on top of a reusable AI skill — a packaged set of instructions that tells Claude Code how to run that transformation, step by step. Each type has its own skill; the OF1 demo skill is the most involved and is described in full below.

What's an AI skill?
A skill is a versioned bundle of instructions, prompts and steps that an AI agent follows to do a specific job. Because Labs experiments are skills, improving how a demo is built means shipping a new skill version — not rewriting the platform — and adding a new experiment type simply means adding a new skill.
The pipeline

The OF1 pipeline

The OF1 demo runs a fixed sequence of steps, grouped into four phases. It always runs in the same order, so every demo is built the same, reliable way.

Thirteen steps · four phases
Steps 01–03
Setup & discovery
Prepare the workspace, crawl the target site, and extract its brand, products and content.
↓
Steps 04–06
EDS provisioning
Stand up the AEM Edge Delivery site, generate page templates, and apply on-brand styling.
↓
Steps 07–11
OF1 provisioning
Author brand voice, content metadata, quick suggestions and CTA templates — the ingredients personalization needs.
↓
Steps 12–13
Review & deploy
Review the generated config, commit it, sync to Edge Delivery, and verify the live preview works.

Some steps run in parallel to save time, and heavier reasoning steps use a more capable model than the lighter ones. The whole sequence is defined by a versioned skill — so improvements to how demos are built ship as a new skill version, and a run can be pinned to a specific version for consistency.

Where it ends up
The finished demo is published to an AEM preview URL of the form https://main--<project>--of1-labs.aem.page/of1. That link is what you share.
Using Labs

Run an experiment

There's nothing to install. Everything happens in the browser at labs.of1.live.

1
Open Labs & sign in
Go to labs.of1.live and sign in with your Adobe account (Adobe IMS). Your session is used to give you access to the workspace Labs creates.
2
Choose an experiment type
Pick OF1 demo, Stardust redesign or Liftoff migration depending on what you want to show.
3
Enter the target URL
Paste the address of the website you want to transform, then submit. Labs queues the run and immediately starts provisioning — you don't need to keep anything open for a hosted (container) run.
4
Wait for the email
A typical run takes several minutes. When it finishes you get an email with the live preview link — or you can watch progress in the Labs UI while it runs.
Interactive runs
Some experiments run in an interactive sandbox instead of a hosted container. For those, Labs gives you a join link and you keep the tab open while it works — the run needs the live connection. Hosted runs need nothing kept open.
Using Labs

Following progress

A run moves through a handful of states. You can see exactly which step it's on at any time.

StatusWhat it means
QueuedSubmitted and waiting to start
ProvisioningSetting up the workspace and AEM site (this can take a couple of minutes)
RunningThe pipeline is executing — each step reports as it starts and finishes
ReadyDone. The live preview link is available and an email has gone out
FailedSomething stalled — you can read the reason and start a new run

While a run is running, the Labs UI shows the current step and a history of completed ones, so a long run is never a black box. When it reaches ready, open the AEM preview link, click Personalize, and you're looking at a working of1 demo of the site you started with.

If a run fails
Runs that stall (for example, if the target site's preview never comes online) are automatically marked failed rather than hanging forever. The failure reason is shown in the UI — usually it's safe to just start a fresh run.
